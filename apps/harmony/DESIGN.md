# 考公云鸿蒙端 · 设计规范

> 唯一事实源：`entry/src/main/ets/theme/Tokens.ets`。**页面里不允许出现硬编码色值、字号、间距。**
> 新增视觉需求 → 先在 Tokens 加令牌 → 再在页面引用。
> 校验脚本（本文件末尾）可自动检出违规。

---

## 1. 设计定位

**暖米底 + 深绿的「护眼阅读」调性。** 与 Web 端**有意不共用色板**：

| | Web 端 | 鸿蒙端 |
|---|---|---|
| 底色 | `#f5f7fa` 冷灰蓝 | `#F5F1E8` 暖米 |
| 主色 | `#1d4ed8` 品牌蓝 | `#4C795B` 深绿 |
| 取舍 | 信息密度优先、品牌识别 | **长时阅读的暖调与低蓝光** |

理由：考公复习动辄单次 30 分钟以上的连续阅读，暖底 + 低饱和绿能显著降低视觉疲劳；
Web 端面向浏览与检索，保留品牌蓝更合适。这是**有意的分化**，不是不一致。

> 若将来要让 Web 也走暖调，Web 已有 `[data-theme="reading"]`（`#f6f1e6` / `#8a5a2b`），
> 可作为对齐的落点——但那是 Web 侧的决策，不在本规范范围。

### 深色令牌（v1.1 新增）

**为什么不做反色**：`#F5F1E8` 直接取反会得到脏灰，暖调尽失；
纯黑底配暖色文本夜间反光过强。所以深色是**另一套独立取值的"深暖灰"体系**，

## 3. 排版 / 间距 / 圆角 / 动效

### 字号（比例约 1.2，以正文 17 为基准）

| 令牌 | 值 | 用途 |
|---|---|---|
| `CAPTION` | 12 | 序号、角标 |
| `META` | 14 | 来源、日期、标签 |
| `BODY` | 17 | 正文（阅读页） |
| `TITLE_S` | 20 | 卡片/列表标题 |
| `TITLE_M` | 24 | 区块标题 |
| `TITLE_L` | 28 | 文章标题 |

> 首版为 12/13/14/15/16/17/22 —— **7 档无比例关系**，13/15 为编外值，已全部归位。

### 行高

`TIGHT 22`（配 META）· `NORMAL 24`（配 BODY 概览）· `RELAXED 30`（配 BODY 正文，1.76 倍）
· `DISPLAY 38`（配 TITLE_L）

### 字号与行高（v1.1 起支持阅读档位）

标尺以正文 17 为基准，比例约 1.2：`12 / 14 / 17 / 20 / 24 / 28`。

**档位系数**：小 `0.88` · 标准 `1.0` · 大 `1.15` · 特大 `1.3`

**缩放策略（v1.4 修订，含一次实测返工）**：

| 类别 | 是否缩放 | 理由 |
|---|---|---|
| 正文、卡片标题、文章标题（`body` / `titleS` / `titleL`） | ✅ 缩放 | 这是阅读密度，用户要调的就是它 |
| 角标、来源、日期、标签（`caption` / `meta`） | ✅ **缩放（v1.4 改）** | 原设计写"固定"，但它们在首页占比最大——来源、日期、序号、关键词全在这两档。用户选「特大」时这些字纹丝不动，**体感就是"字号调节无效"**。用户选大字就是要都看得清 |
| 区块标题（`titleM`） | ✅ **缩放（v1.4 改）** | 同上 |
| 系统绘制的导航栏标题 | ❌ 固定 | 由框架绘制，应用改不了（这才是真正"不影响导航标签"的那一项） |

> **教训**：当初"不影响导航标签"的理由，被错误地扩大到了 `caption/meta` 两个**内容**档位。
> 区分标准应该是「这是内容文字还是框架绘制的界面文字」，而不是"看着像小字"。

**行高必须联动**：`lineHeight = fontSize × 系数`（正文 1.76、概览 1.41、角标 1.57、标题 1.36）。
只放大字号不放大行高，中文会挤成一团。

### ⚠️ 主题与字号切换必须让内容层重建（v1.4 踩坑）

字号与颜色令牌**全局读 `AppStorage`**（`KFont.scale()` → `AppStorage.get('fontScale')`），
这条路**不在 ArkUI 的依赖追踪范围内**——框架只把"在 `build()` 里**直接读到**的状态变量"记为依赖。

所以**只在组件上声明 `@StorageLink('fontScale')` 是不够的**：改设置不重绘，表现为"调节无效"。

**做法**：把「深色 + 字号」写进 `ForEach` 的 key，key 一变整棵子树重建，令牌随之重新取值：

```ts
ForEach([`${this.darkMode ? 'd' : 'l'}-${this.fontScale}`], () => {
  this.content()   // 或 headerRow + content
}, (key: string) => key)
```

代价是切换设置时丢一次滚动位置——设置是低频操作，可接受。
`Scroll` 只允许一个子组件，所以外面必须包一层 `Column`。

**为什么用离散档位而不是滑杆**：阅读排版需要可预期的结果（行高、折行位置），
滑杆会造出无数中间态，用户反而找不到合适的阅读密度。

### 间距（4 的倍数）

`HAIR 2` · `XS 4` · `S 8` · `M 12` · `L 16` · `XL 20` · `XXL 24` · `XXXL 32` · `PAGE 16`

> 首版散落 2/6/10/13/14/18/21/26 等编外值（44 处魔数），已归位。

### 圆角

`XS 4` · `S 8` · `M 10` · `L 14`（卡片）· `XL 20`（浮层顶角）· `FULL 999`（胶囊）

### 动效

`XS 120` · `SM 160` · `MD 250` · `LG 400`（ms，与 Web 端档位一致，便于跨端节奏统一）

## 4. 组件约定

| 组件 | 规格 |
|---|---|
| **卡片** | `SURFACE` + `KSpace.L` 内边距 + `KRadius.L` + 暖调阴影（`KShadow.CARD_*`） |
| **胶囊标签** | `FULL` 圆角，水平 `KSpace.L` 内边距，**触摸目标高度 44** |
| **列表行** | 整行可点，`constraintSize({ minHeight: 44 })`，按压态 `SURFACE → SURFACE_ALT` |
| **图例 chips** | 用标注色做底 + `INK` 字；**图例不承担点击**，点击交给右侧「标注清单」 |
| **底部浮层** | `HINT_SOFT` 底 + 顶部双圆角 `XL` + 外层轻遮罩，**遮罩整屏可点关闭** |
| **设置面板** | `view/SettingsSheet.ets` 可复用组件；含字号档位 + 深色开关 + **实时预览行**；面板只负责内容，浮层容器由调用方提供 |
| **错误态** | 白卡 + `DANGER` 标题 + `SUB` 说明 + 44 高「重试」按钮（**不白屏**），措辞区分「没联网 / 服务异常 / 未部署」 |
| **骨架屏** | 结构与真实卡片一致，避免内容到达时的布局跳动 |

### 无障碍硬指标（已落地）

- 交互元素高度 **≥44vp**（日期胶囊、列表行、图例、清单条目、按钮已全部满足）
- 文本对比度：正文与次要信息均 ≥4.5:1（见 §2）
- 不依赖颜色单独传达信息：标注除底色外**同时**有类型文字标签

### v1.3 补齐：数据层与信息可达性

| 优先级 | 项 | 实现方式 |
|---|---|---|
| P0 | **离线缓存** | 文件缓存（非 Preferences——manifest 40KB 超其单值限制）。先网络、失败回落缓存；缓存写入失败不阻断功能 |
| P0 | **跨日检索** | 本地索引：manifest 已含全量文章的标题/来源/日期，**零网络、离线可用**。边界：只检索标题与来源，不做全文（全文需端上存 2MB+ 正文，代价不值；应改为构建期产出轻量索引） |
| P1 | **冷启动秒开** | `ContentService.cachedXxx()` **同步**读缓存渲染首帧，再后台刷新。必须同步——异步读会先闪一帧空白 |
| P1 | **空态设计** | 「这一天没有内容」给出可执行方向（切日期 / 用检索）；检索无结果时提示换更短关键词或换来源名 |
| — | **离线态如实标注** | 缓存内容一律标注「离线内容（缓存于 x 前）」，**不冒充"刚刚更新"**——时政的时效性不允许误导 |

> 缓存取舍：`ContentService.loadWithCache` 是**先网络后缓存**，不是先缓存后网络。
> 缓存只做兜底：在线时必须拿最新内容。

### v1.4 补齐：朗读（TTS）

| 项 | 做法 |
|---|---|
| **朗读** | 系统 TTS（`@kit.CoreSpeechKit`），**离线引擎**（`online: 0`）——通勤场景经常没网 |
| **按段落逐句提交** | 整篇一次提交只能拿到"开始/结束"，**无法知道读到哪一段**。逐段提交才能做跟随高亮 + 自动滚动——这才是"听"的体验核心：用户不方便盯屏幕，需随时瞄一眼确认位置 |
| **从当前段落开始** | 不是从头：通勤时用户往往已看了前半段，从头发起等于让他重听一遍 |
| **当前段落加底色跟随** | **只加底色、不加内边距**——加内边距会让整篇版式随朗读位置跳动，读者会看着文字上下窜 |
| **段落间留 320ms 停顿** | 纯连读没有换气感，听起来像机器报菜名 |
| **速度四档** | 0.8 / 1.0 / 1.25 / 1.5（持久化）。通勤时 1.25× 是刚需——省时间且不失可懂度 |
| **离开页面即停** | `aboutToDisappear` 调 `Speech.stop()`，否则返回首页后还在念 |

**边界（如实说明）**：不做后台播放（需 AVSession + 长时任务，是另一个量级的改造）、不做锁屏控制。引擎创建失败时页面**如实提示**，不静默失败。

## 6. 应用图标

**概念：一页被划亮的书。**

| 元素 | 取值 | 用意 |
|---|---|---|
| 底盘 | `#4C795B` 满幅 | 品牌色打底，保证启动器网格上的识别度 |
| 书页 | `#F5F1E8`，右上折角 | 折角让"这是一页纸"一眼可辨，不靠细节堆砌 |
| 文字线 | `#A9C3B2` | 用品牌绿的浅调，不引入第二套色相 |
| 高亮条 | `#FFE7A0` | **产品的核心动作**（给原文划考点）。刻意取 App 内「考点」标注色，让图标与功能呼应 |

**规范与约束**：

- 满幅正方形，**不在画布内自画圆角**——圆角由启动器遮罩施加，自画会被二次裁切露出透明缺口。
- 主形留边 44/216 ≈ 20%，小于系统裁切半径，保证任何遮罩形状下都不被切到。
- 内容块（76–140）在书页（38–178）内**上下等距留白 38**，避免视觉重心下沉。
- 48px 下仍能认出「书页 + 高亮条」，已用多尺寸预览验证。

**矢量源与构建**：


## 7. 跨端设计一致性

### 现状（纠正一个此前的误判）

**Web 端默认主题本来就是暖色**：`Base.astro` 里
`const theme = saved || (prefers-color-scheme: dark ? "dark" : "reading")` —— 默认 `reading`（纸感暖底）。
此前仅凭 `:root` 兜底块就判定"Web 是冷蓝体系"，是**错的**。

真正的不一致只有一处：**主色相**。Web 的 `reading` 主题主色是棕金 `#8a5a2b`，原生端是深绿 `#4C795B`。

### 已做的对齐（2026-09-11）

以原生端为主形态，Web 的 `reading` 主题向它靠：

| 令牌 | 原值 | 现值 | 说明 |
|---|---|---|---|
| `--primary` | `#8a5a2b` 棕金 | `#4a7355` 墨绿 | 对比度实算：纸底 4.81:1、白底 5.42:1，均达 AA |
| `--primary-deep` | `#5c3a1a` | `#35563e` | 深态/文字态 |
| `--primary-soft` | `#f1e6d4` | `#e5ede5` | 浅绿底（原为棕黄底） |
| `--hl-yellow` | `#f3e0a4` | `#ffe7a0` | **与原生端考点色完全一致** |
| `--hl-green` | `#d6e8c6` | `#c8e6c9` | **与原生端观点色完全一致** |
| `--hero-end` | `#7a5226` | `#466a50` | 品牌区渐变终点跟随主色 |

**为什么是 Web 改而不是 App 改**：App 是主打形态且已实机验收；Web 的令牌本就集中（`--primary` 使用面 46 处、
零硬编码残留），改一处全线生效，风险可控。

### 有意保留的差异（不是遗漏）

| 项 | Web | 原生端 | 理由 |
|---|---|---|---|
| 标注色板 | 2 底色（黄/绿）+ 下划线 + 加粗 | 4 底色（+术语蓝/数字指标粉） | Web 的 `HighlightStyle` 是**共享契约**且服务于**用户荧光笔**功能，加色要动契约 + API；原生端标注是只读展示，不与用户笔迹混用同一套样式 |
| 底色 | `#f6f1e6` | `#F5F1E8` | 差值 1/255 量级，肉眼不可辨；不必为形式统一而制造 churn |
| logo 字体 | 行楷 `HYXiaoYaoYouJ` | 系统字体 | 原生端不引入商用未授权字体 |

## 8. 违规自检脚本

已入库为可重复执行的脚本（不是文档里的一次性命令）：

```bash
node apps/harmony/scripts/audit-arkts.mjs
```

检查以下硬约束（这些是"编译期不一定报错、但会让设计体系悄悄崩掉"的问题）：

1. 相对导入全部可达；
2. 不使用 `any` / `unknown`（ArkTS 硬性限制）；
3. 无未使用的导入（按 `as` 别名解析，避免误报）；
4. 无定义后未被引用的 `@Builder`；
5. **`Tokens.ets` 之外零硬编码色值**；
6. 无残留的**旧式常量令牌引用**（令牌已改为方法，漏改会静默失效）。

期望输出：

```
✓ 全部通过
```

失败时 `exit 1`，可直接接进 CI。
