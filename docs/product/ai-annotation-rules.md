# AI 概括与标注规则

## AI 负责的内容

1. 为首页生成 80-120 字中文概括。
2. 识别原文中的观点句。
3. 识别适合申论积累的考点。
4. 识别政策术语。
5. 为政策术语生成 30-80 字短释义。

## AI 不负责的内容

- 不改写、删减或替换原文。
- 不直接生成 HTML、CSS 或 JavaScript。
- 不添加原文没有的事实、数字、人物或政策结论。
- 不生成整篇文章解释。
- 不生成完整申论范文。

## 标注类型

| 类型 | 含义 | 阅读页展示 | 每篇建议数量 |
|---|---|---|---:|
| `viewpoint` | 明确判断、立场、价值取向或结论 | 加粗 | 2-5 |
| `exam_point` | 政策措施、问题原因、治理方法或对策表达 | 高亮 | 3-8 |
| `term` | 政策概念、治理术语、专业名词或新提法 | 下划线 + 悬停释义 | 1-5 |
| `figure` | 纯数字/指标值（增速、总额、覆盖率、时间节点等） | 原文高亮标记；**不生成卡片**（2026-08-22 拍板：数字不背，标记即可） | 1-10 |

建议下限是质量提示，不因不足自动判失败。发布门禁硬限制每篇最多 `viewpoint=5`、`exam_point=8`、`term=5`、`figure=10`，超过任一上限即记录语义质量错误。

## 输出协议

AI 返回原文片段和类型，程序负责重新计算位置：

```json
{
  "summary": "首页概括",
  "annotations": [
    {
      "paragraphIndex": 0,
      "text": "原文中的连续片段",
      "type": "viewpoint",
      "explanation": ""
    }
  ]
}
```

程序必须：

- 在对应段落中定位 `text`。
- 计算 `start` 和 `end`。
- 校验文本与偏移一致。
- 拒绝空片段、跨段片段和越界片段。
- 丢弃无法定位的单条标注并记录原因。
- 使用浏览器一致的 UTF-16 code unit 计算 `start/end`。

## 状态字段

- `pending`：等待 AI 处理，不包含概括或失败原因。
- `ok`：概括和 AI 元数据完整，标注数组可以为空。
- `error`：保留原文，标注数组为空，并记录 `aiError`。

历史文章可暂时缺少 AI 状态；任何经过新 Pipeline 处理的文章都必须明确写入状态、模型、Prompt 版本、生成时间和原文 hash。

## 阅读显示

- 原文模式：隐藏全部 AI 标注，但保留用户标注。
- AI 标注模式：显示三类 AI 标注，并保留用户标注。
- `viewpoint` 使用加粗。
- `exam_point` 使用高亮底色。
- `term` 使用下划线。
- 术语释义使用鼠标悬停显示，移开后隐藏。
- AI 标注是只读内容数据，用户不能删除它。

## 失败降级

- AI 失败不阻止原文发布。
- `aiStatus` 必须标记为 `error`，并记录可诊断的失败原因。
- 失败文章不显示 AI 模式或显示空状态，而不是伪造标注。
- 后续可通过重试任务重新生成 AI 数据。

## 日报数量门禁

- Pipeline 以最近一次 `ok` 或 `degraded` 报告中的正数 `candidates` 和 `articles` 为基线。
- 当本次任一数量低于该基线的 50% 时记录 `below_half_baseline`，不得静默当作正常发布。
