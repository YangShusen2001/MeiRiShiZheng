# 提案 0014：南方时评抓取修复 + 申论精读栏目合并

> 状态：已批准并实现。用户确认：扩池到 30（limit×3）、AI 评分挑重点（方式 B）；今日谈最多 2 条、limit=10 保持不变。

## 1. 背景

- 用户反馈：**南方时评（南方网·广东申论素材）的正文一直为空**，请审查并写提案。
- 需求：把 **今日谈（半月谈·申论素材）** 与 **南方时评（南方网·广东申论素材）** 移动到「申论精读」栏目下。

## 2. 调研结论：南方时评正文空的根因

### 2.1 现状

- 源配置：`南方时评`，`slot=nf`，`page=https://opinion.southcn.com/`，`mode=pubdate`，`href_re=opinion\.southcn\.com/node_`。
- 实际表现：最近多期 digest 的 `south-review` 栏目 `items` 为空（08-17 为空数组）；偶有候选也是频道页/导航链接，剪藏正文为空 → `clip_error` 丢弃（经 0013 的剪藏失败显性化后可看到）。

### 2.2 根因：`href_re` 过宽，把频道页当文章

对 `opinion.southcn.com` 列表页的 275 个链接做分类（已实测）：

| 类型 | 数量 | 形态 | 是否有正文 |
|---|---|---|---|
| 真实文章 | 62 | `node_XXXXXXXX/YYYYYYYY.shtml` | ✅ 有 |
| 频道页 | 20 | `node_XXXXXXXX`（栏目首页） | ❌ 无正文 |
| 其他频道导航 | 44 | `car/edu/live/.../node_*.htm` | ❌ 无正文 |

现 `href_re=opinion\.southcn\.com/node_` **三类全部匹配**。`mode=pubdate` 按 HTML 出现顺序取前 `limit` 个候选，而**频道页/导航链接排在 HTML 前部**，把 `limit=10` 的额度占满 → 真实文章进不来；频道页没有正文 → `clip_article` 提取 <2 段 → 剪藏失败 → 栏目空/正文空。

### 2.3 实测验证

- 收紧为 `opinion\.southcn\.com/node_[0-9a-f]+/[0-9a-f]+\.shtml` 后，`_extract_pubdate` 产出 10 个候选，**全部是真实文章**（带正确日期，如 08-15/08-17）。
- `extract_paragraphs` 对真实文章（如 `node_87fa4020d8/62a20fbd21.shtml`）实测能提取 **6 段正文** → **clip 逻辑本身没问题**，纯是候选选错。

## 3. 方案

### 3.1 修复南方时评（两处保持一致）

把 `南方时评` 的 `href_re` 收紧为：

```text
opinion\.southcn\.com/node_[0-9a-f]+/[0-9a-f]+\.shtml
```

- `pipeline/config.json`：`南方时评` 条目。
- `pipeline/src/kaogong/sources.py`：`DEFAULT_SOURCES` 里的 `Source("南方时评", ...)`。
- 收紧后导航/频道链接不再匹配，真实文章按顺序入选；`limit=10` 保持不变。

### 3.1.2 「挑重点」的挑选策略（limit=10 怎么选）

**现状**：`_extract_pubdate` 按 HTML 顺序取前 10 个候选（再在 `fetch_candidates` 里过滤当天）——只保证"顺序靠前"，不保证"当天"和"重要"，这也是最近栏目常空的原因之一。

**实测**：收紧正则后，前 10 篇真实文章的日期跨度约 10 天（08-07 ~ 08-17），每天约 2-5 篇；以 08-17 为例，前 10 篇里含 3 篇当天文章。

**优化策略（推荐）**：

1. **扩池**：候选收集上限从 `limit`(10) 提到 `limit × 3`(30)，按 HTML 顺序抓 pub date（约 30 次请求、~45 秒，可接受）。
2. **当天过滤**：`fetch_candidates` 过滤 `c.date == target`（现有逻辑不变）。
3. **取前 limit**：
   - 当天候选 ≤10 篇 → **全部收录**（保证当天文章不漏）；
   - 当天候选 >10 篇 → 需要挑重点，两种方式：
     - **方式 A（免费）**：按列表页 HTML 顺序取前 10（列表通常最新/推荐在前）；
     - **方式 B（可选，AI 挑重点）**：用审核 Agent 的 `judge_item` 对当天候选评分（相关性/标题/摘要，同一套黄金标准），按 score 降序取 top 10——每天约 10-20 次 DeepSeek 调用，成本低，且与审核 Agent 复用。

### 3.2 栏目合并（`pipeline/src/kaogong/build.py`）

「申论精读」栏目从 `shi+qst+xh+rm` 扩展为：

```text
申论精读 = 人民网时评 + 求是网 + 新华时评 + 人民日报评论 + 今日谈(最多2条) + 南方时评
```

- `byt` 保持**最多 2 条**（今日谈是精编栏目，原语义保留）。
- 删除独立的「今日谈（半月谈·申论素材）」与「南方时评（南方网·广东申论素材）」两个栏目。
- 栏目顺序：national → essay（含新并入的两类）→ 地区 → 广东政策。

## 4. 影响

- digest 结构变化：不再有 `south-review` / `today-talk` 独立栏目，全部并入 `essay`。
- 前端按 digest 动态渲染栏目，**无需改前端**。
- 下次「抓取」生效；`content/_reports` 里旧报告不追溯。

## 5. 验证

1. `fetch_source(南方时评)` 只产出文章链接（无频道页）。
2. `build_digest` 单测：`byt`/`nf` 进入 `essay` 栏目，无独立栏目。
3. 管道测试全绿。
4. 下次抓取后检查：南方时评文章正文非空、申论精读含今日谈与南方时评。

## 6. 已确认决策（2026-08）

1. 今日谈保持「最多 2 条」✅。
2. 南方时评 `limit=10` 保持，候选池扩到 **30（limit×3）** ✅。
3. 当天候选超上限时用 **方式 B（AI 评分）** 挑重点：`fetch_candidates` 按槽位分组，超上限时用审核 Agent 的 `judge_item` 按 score 降序取 top cap；无 key 时退化回列表顺序 ✅。
