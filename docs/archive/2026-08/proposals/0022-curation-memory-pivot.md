## 1. 核心判断（用户确认）

1. **产品北星翻转**：从"时政文章聚合站"（内容终点）→ "以考点为单元的备考记忆系统"（内容变原料）。
2. **文章角色降级**：文章从"读的终点"变为"考点的出处与求证材料"；用户每天的第一动作从"看今天有什么"变为"复习今天到期的卡"。
3. **加量决策反转**：0008（扩大来源/翻页）与 0014（扩池 30）的目标是"网页太少"；本提案确认"少而深"优于"多而浅"，候选池只用于选材，不再全部发布。需要在实施时落一条 ADR 记录此反转。

## 3. 主线池（替代「主题轮换」）

用户确认：**政策有连续性，一段时期内并行或择一重**；每日学习目标跟随当前政策主线，而非机械轮换 30 个主题。

### 3.1 数据模型（`content/policy-lines.json`，人工维护）

```json
[
  {
    "id": "15w-plan",
    "name": "十五五规划建议",
    "status": "active",              // active | retiring | archived
    "window": { "start": "2025-10-23", "end": null },
    "retireHint": "近 14 天相关文章占比 < 阈值时提示人工审查（仅提示，不自动退休）"
  }
]
```

### 3.2 维护方式（用户拍板：人工）

- 纯人工起步：每 1–2 周 15 分钟更新（建新线 / 停旧线 / 改状态），在选材工作台或直接改 JSON。
- **AI 自动归纳主线暂不做**——AI 归纳主线等于让 AI 替用户做政策判断，且每年只变更十几次，不值得自动化。

### 3.3 与考点库的关系

主线 → 考点 → 卡片 → 文章/句子（四层）。0021 的「结构化考点库」（🥈）与「考点跨政策聚合」（🥉）在本模型下自然成立；0021 已产出的 30 张卡（十五五规划建议 + 政府工作报告）即首批主线资产。

## 4. 每日选材漏斗（AI 只排序，不打分）

用户拍板：**槽位制** + **AI 只排序不打分**（防止连续分幻觉）。

```
75 候选
  ↓ ① 粗筛（减法，不做价值判断）
     来源权威性分级（人民日报/新华社/中国政府网/求是/半月谈=1.0，省级=0.7，地方=0.4）
     可学习性（AI 标注密度 + 金句数量，已有数据零成本）
     完整性（复用 judge_item 5 维）
     标题级去重（同事件多源保权威性最高者；不引入 embedding/向量）
     时效（当日/近 48h）
  ↓ ② 主线归属：AI 判「归属哪条活跃主线」；归不了 = 素材库（可作补剧）
  ↓ ③ 槽位分配（按等级排序，AI 输出等级 + 一句话理由）
  ↓ ④ 人工确认（全文预览 → 留/换 → 顺手改正主线归属 → 箭头微调，可选）
  → 2–5 篇定稿
```

### 4.1 槽位定义（用户拍板：头版要闻可脱离主线池）

| 槽位 | 内容 | 来源偏好 | 主线约束 |
| --- | --- | --- | --- |
| 1 | 头版要闻：当天最重要政策/会议/文件 | 权威源 | **允许脱离主线池**（追当日真热点） |
| 2–3 | 申论精读：评论、解读、时评（人民日报重点解析归此） | 人民网评/半月谈评论/南方时评 | 绑主线 |
| 4 | 考点提炼：密集数字/措施/提法的文件类（产卡最多） | 政府文件/规划/部委发文 | 绑主线 |
| 5 | 多样性补充：今日主线未覆盖但高价值的临时热点 | 全源 | 绑主线（跨主线检查） |

### 4.2 等级制输出

AI 对每篇只输出等级（S/A/B/C）+ 一句话理由；**程序负责排序与槽位分配**（延续「AI 出意图、程序做决定」红线）。第一版先「AI 只排序不打分」跑两周，观察哪个槽位常空、哪种理由用户不听，再决定是否引入正式打分。

### 4.3 质量标准变化

精选制下每篇都必须过质量门禁（定位错误等为 0 或仅允许人工确认残留）；失败文章进素材库，**不静默发布**（沿用 0003/0009 的现有门禁语义，仅将「发布」口径收窄为「入选今日目录」）。

## 5. 关系标注（箭头）：AI 生成初稿 + 人工修正

用户拍板：**AI 也标注；如果错了，用户在工作台改**。

### 5.1 数据模型（`ClippedArticle.aiRelations`，内容数据，不与用户数据混合）

```json
[
  {
    "id": "rel-15w-001",
    "paragraphIndex": 2,
    "anchor": "ai-2-12-30-viewpoint",   // 引用已校验的 AiAnnotation.id（中心句）
    "points": [
      { "annotationId": "ai-3-5-20-exam_point", "kind": "support" }
    ],
    "kind": "support",
    "aiGenerated": true,
    "editedAt": null,
    "editedBy": null
  }
]
```

- 新类型沿用现有约束：AI 只输出关系意图（from/to/kind），**引用已存在的标注 id**，程序校验引用有效、数量上限（每段 ≤1 中心 + ≤5 支撑）；支撑点**允许跨段**（2026-08-22 实现校正：真实总分结构常跨段，箭头 overlay 跨段绘制）；不新增第二套文本定位逻辑。
- `kind` 枚举：`support`（支撑）/ `explain`（解释）/ `example`（举例）/ `contrast`（对比）。

> 2026-08-22 拍板修订：**AI 自动生成关系标注关闭**（效果不可控，用户明确"看着难受"）；`aiRelations` 由选材工作台**人工创建/编辑**（拖线添加），AI 辅助生成保留为可选能力（`relation_ai.py` 未被调用）；渲染样式由工作台统一配置（样式画廊挑选）。

- 人工修正写回 `content/`（内容数据，非用户数据），沿用 `.bak` 备份 + 一键回退（0013 已验证的模式）。
- **管道重跑 AI 时不得覆盖人工修正**：若 `editedAt > aiGeneratedAt`，该关系标注标记 `locked`，重跑时保留人工版并提示；人工也可显式解锁重置为 AI 版。
- 审计字段：`editedAt` / `editedBy` / `aiGenerated` 保留来源与版本痕迹。

### 5.3 渲染（线上站）

文章容器内 absolute SVG overlay + 贝塞尔曲线 + `marker-end` 箭头；锚点 span 已有 DOM（`readerSegmentsToHtml`），`getBoundingClientRect` 取坐标；`ResizeObserver` + `document.fonts.ready` 重算；`opacity 0.3–0.5`，悬停/点击中心句时显示该簇；`prefers-reduced-motion` 禁用动画。颜色沿用 DESIGN.md token（金色系），不与三色标注冲突。移动端显示「段落结构卡片」（中心句 + 支撑点列表）作为兜底。

## 9. 视觉语言：手绘批注层 + 手账风（并入本提案，用户 2026-08-22 拍板分层）

### 9.1 分层原则（用户拍板）

- **手绘批注层**（箭头、荧光笔、下划线、考点卡片、复习界面、选材工作台）= 手绘本 / 蜡笔风。
- **精读正文层** = 印刷感（宋体/楷体阅读字体），只叠加手绘批注（"纸上的标注"）。
- 理由：① 可读性——正文手写体会造成长文阅读疲劳（与"别人怎么看完 59 篇"的担忧同源：形式不能压过内容）；② 心智匹配——复习/记忆场景是"文具手账"心智，比"编辑部"更贴合改赛道后的产品；③ 手绘层与正文层分层后，两者互不拖累。

### 9.2 四件套

| 部件 | 技术 | 说明 |
| --- | --- | --- |
| 箭头 | **rough.js** 手绘曲线 + 箭头头（高 roughness、多层半透明笔触、`feTurbulence` 抖动） | 复用 §5.3 的 SVG overlay 方案，交互不变（端点仍是 span 锚点），只把直线替换为蜡笔曲线；**不用千图网图片素材**（版权风险，rough.js 效果已足够接近目标质感） |
| 荧光笔 / 下划线 / 框选 | **rough-notation**（highlight / underline / box，书写动画） | 荧光笔颜色与现有三色语义映射：考点=蜡笔黄、观点=蜡笔青、术语=蜡笔橙（默认值，可调）；`prefers-reduced-motion` 关闭书写动画 |
| 纸感版式 | CSS 纸张噪点纹理 + 卡片不规则圆角/微旋转 + 纸影 | DOM 结构不动，只加样式层；移动端 44px 触控目标等既有约束保留 |
| 字体 | **站酷快乐体**（标题/标注/UI）+ **手书体/楷体变体**（温润气质）双字体，`font-display: swap` + 回退链 | 用户拍板两个都要；全部先经**商免清单核验**（font.luhui.net 收录的明确授权来源），复用现有 `fonts.py` 子集化管道按需子集 |

### 9.3 颜色

- 保留现有豆沙绿护眼 token 系与 DESIGN.md 明暗双主题，只换质感（纸面/蜡笔），不改色板语义。
- 标注三色在手绘层沿用"考场笔迹"色系，保持与现有 `ai-exam-point` / `ai-viewpoint` / `ai-term` 语义一一对应。

### 9.4 性能与无障碍

- rough.js / rough-notation 每次渲染随机生成：**生成后静态化缓存**（一次性输出 SVG），不做滚动重绘；书写动画仅在首次进入视图时播放一次。
- `prefers-reduced-motion: reduce`：禁用书写动画与箭头动效（沿用 DESIGN.md §6 既有门禁）。
- 屏幕阅读器：箭头/荧光笔是无语义装饰，标注语义继续走现有 `aria-label` / `data-explanation` 通道，不改变内容可访问性。

### 9.5 工作量（相对估算）

箭头 1-2 天 + 荧光笔 0.5-1 天 + 纸感/组件 3-5 天 + 字体选型与子集化 1 天，叠加在 C 阶段前端实现中；DESIGN.md 需同步重写（§12 待确认项）。

## 11. 明确不做（防过度工程）

- ❌ embedding / 向量相似度 / 向量库（65 篇规模，标题级去重足够）
- ❌ 个性化推荐系统（最多"主题偏好"级别记录）
- ❌ AI 自动定稿（选材是编辑判断；AI 只建议，用户确认）
- ❌ AI 自动归纳主线池（人工维护，已拍板）
- ❌ 移动端箭头编辑（工作台定位 PC）
- ❌ **正文手写体**（分层已拍板：正文保持印刷感）
- ❌ 千图网等图片素材贴图（版权风险；rough.js 自绘代替）
- ❌ 动效炫技（沿用既有频率门禁，只做标注/箭头书写动画）

## 12. 用户已确认决策（2026-08-22）

1. 槽位制（头版要闻 / 申论精读 ×2 / 考点提炼 / 多样性补充，5 槽、下限 2）。
2. AI 只排序不打分（等级 + 理由，程序排序）。
3. 每日学习目标 = 主线池跟踪（人工维护 JSON），不做主题轮换。
4. 头版要闻槽允许脱离主线池（追当日真热点），其余槽绑主线。
5. 箭头编辑器挂在新工作台，选材与编辑一体化；阅读器迁 React island 为前置。
6. 关系标注由 AI 生成初稿；**有错由用户修改**（写回内容数据，人工修正不被重跑覆盖）。
7. 复习逻辑整体重设计（统一 FSRS：卡片/错题/每日一练）。
8. 视觉采用**分层方案**：手绘批注层（箭头/荧光笔/卡片/复习/工作台）+ 印刷正文层（只叠加手绘批注）。
9. 中文手写字体**两个都要**（站酷快乐体 + 手书体/楷体变体），先过商免清单核验，复用现有字体子集化管道。
