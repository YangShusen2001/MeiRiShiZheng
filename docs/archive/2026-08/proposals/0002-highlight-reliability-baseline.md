# 提案 0002：用户划线可靠性基线修复

- **状态**：已接受，等待 TASK-0007 实施
- **日期**：2026-08-14
- **范围**：用户划线 API、D1 数据模型、阅读页交互和浏览器测试

## 背景

现有划线纯函数和 API 单元测试通过，但用户实际交互存在明显缺陷。自动测试目前没有覆盖真实 Selection、网络失败、刷新恢复、移动端长按和多客户端并发，因此“测试通过”不能证明划线功能正常。

当前实现已经解决旧版本的文本首次匹配、`surroundContents()` 失败和样式不能叠加问题，但新的整段重写方案引入了数据一致性风险。

## 已确认问题

### P0：先删后插导致数据丢失

`apps/web/src/pages/read/[id].astro` 编辑一个区间时，会删除该段全部旧记录，再逐条创建新记录。删除成功后发生断网、页面关闭或任一创建失败，会永久丢失整段或部分划线。

### P0：旧迁移生成不可见划线

`0005_highlight_styles_offsets.sql` 给旧记录写入空样式和零长度偏移，`0006_drop_highlights_style.sql` 随后删除旧样式字段。若任一环境存在旧数据，旧划线会不可见且无法恢复样式。

当前产品没有真实生产用户，但本地、预览和未来迁移仍必须有明确策略，不能用无效默认值伪装迁移成功。

### P1：加载和编辑存在竞态

页面在划线 GET 完成前已经允许编辑。初始请求稍后返回时会覆盖刚完成的本地状态，造成页面与服务端不一致。

### P1：互斥锁静默丢弃操作

当前 `reconcileBusy` 在保存中直接返回，第二个用户操作不会排队，也没有失败提示。

### P1：注释与渲染切片错误绑定

注释按完全相同的 `start:end` 绑定在样式切片上。样式叠加、切分或合并后，注释可能静默丢失；页面也没有完整的查看和编辑入口。

### P1：缺少移动端和真实浏览器测试

页面主要监听 `mouseup/mousedown`，没有完整处理移动端长按选区、`selectionchange`、视觉视口和浮层越界。

## 决策

1. 不继续在前端用多次 DELETE/POST 模拟整段原子替换。
2. 增加服务端原子段落替换或原子样式操作 API，并包含版本冲突检测。
3. 划线初始数据加载完成前禁用编辑；保存失败必须可见并重新同步。
4. 用户注释与可自动切分的样式 span 分离。
5. 加载旧划线时校验 `record.text` 与当前段落切片一致，内容漂移不能静默标错位置。
6. 在任何环境执行破坏性迁移前增加升级测试和明确的数据保留/重建策略。
7. 引入 Playwright 覆盖桌面、移动端、刷新、弱网和失败恢复。

## 实施阶段

### 阶段 A：数据安全

- 原子保存 API。
- 版本或 compare-and-swap 冲突检测。
- API 错误可见和失败重新同步。
- 暂停无回填策略的破坏性迁移。

### 阶段 B：交互完整性

- 加载前禁用编辑。
- 保存队列或保存中禁用操作。
- 单独移除荧光笔、下划线或全部样式。
- 注释查看、编辑和删除。

### 阶段 C：移动端和回归

- 支持 `selectionchange` 和触控选区。
- 统一浮层视口定位。
- Playwright 浏览器和移动端测试。
- 网络失败、刷新和并发故障注入测试。

## 验收标准

- [ ] 任一步网络失败后，刷新页面不会丢失原有划线。
- [ ] 同段并发编辑不会静默覆盖已确认成功的数据。
- [ ] 页面加载完成前不能基于未知快照编辑。
- [ ] 保存失败有可见提示并可以重试。
- [ ] 用户可以单独移除一种样式。
- [ ] 注释在样式切分和合并后按明确规则保留。
- [ ] 文章内容变化时不会把旧划线渲染到错误文字。
- [ ] iOS Safari 和 Android Chrome 的长按选区可用。
- [ ] 浏览器级回归覆盖创建、叠加、删除、刷新和失败恢复。
